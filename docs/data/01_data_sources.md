# Data Sources

## SRC-001 — NetsLab-5G-ORAN-IDD

- **Source:** NetsLab-5G-ORAN-IDD
- **Provider:** NetsLab
- **Dataset:** https://www.kaggle.com/datasets/netslabdemo/netslab-5g-oran-idd/data
- **Access date:** 2026-09-27
- **License:** Creative Commons Attribution 4.0 International (CC BY 4.0)  
  https://creativecommons.org/licenses/by/4.0/
- **Failure Family:** F1 — Security / anomalous network activity

### Role in the Project

The dataset provides 5G/O-RAN network traffic and lower-layer telemetry used as
technical evidence for development and evaluation of the DAICP MVP.

### Initial Development Subset

| Category | Network Evidence | Lower-Layer Telemetry |
|---|---|---|
| Benign | `benign.pcap` | `benign.txt` |
| DDoS | `ddos_icmp_hping3.pcap` | `ddos_icmp_hping3.txt` |
| DoS | `icmp_nping.pcap` | `icmp_nping.txt` |
| BruteForce | `ftp_hydra.pcap` | `ftp_hydra.txt` |
| Probe | `portscan_masscan.pcap` | `portscan_masscan.txt` |
| Web | `web_xss.pcap` | `web_xss.txt` |

### Data Interpretation

- `.pcap`: raw network traffic evidence.
- `.txt`: lower-layer 5G/O-RAN telemetry.
- Category/scenario: dataset label used to identify the represented condition.

Only a selected subset is used during initial development. Additional scenarios
may be incorporated during evaluation if required.

## SRC-002 — CoreOps

- **Source:** CoreOps — Towards Intelligent 5G Core Management
- **Provider:** CoreOps Research Team
- **Dataset:** https://huggingface.co/datasets/zixuan0615/CoreOps
- **Code Repository:** https://github.com/qinzixuan-bupt/CoreOps
- **Access Date:** 2026-10-14
- **Dataset License:** Creative Commons Attribution 4.0 International (CC BY 4.0)
  https://creativecommons.org/licenses/by/4.0/
- **Code License:** Apache License 2.0 (GitHub repository)

### Role in the Project

CoreOps provides operational logs, network function metrics, and
fault-injection ground truth from experimental 5G Core environments.

The dataset complements SRC-001 by supporting the development and
evaluation of evidence-grounded Root Cause Analysis for operational
network failures.

### Initial Development Subset

The initial subset uses the CoreOps-22NFs testbed.

| Component | Selected Data | Purpose |
|---|---|---|
| Ground Truth | `fault_labels.json` | Identify injected faults and affected NFs |
| Injection Records | `injector_run_*.log` | Verify fault injection events |
| Operational Logs | `logs/*.log` | Investigate NF behavior and errors |
| Fault Windows | `aligned_fault_window.json` | Identify incident time intervals |
| Global Metrics | `global_matrix.csv` | Analyze NF availability |
| NF Metrics | Selected files from `per_nf0525/` | Analyze resource and operational metrics |
| Topology | `topo.yaml` | Provide infrastructure context |

### Initial Evaluation Scope

The initial evaluation will focus on selected operational fault families:

- Network connectivity failures.
- Network function availability failures.
- Resource contention and performance degradation.

Scenarios will be selected according to ground-truth reliability
and available operational evidence.

### Data Interpretation

- Logs represent operational events generated by 5G Core functions.
- Metrics provide observations of network function behavior.
- Fault labels identify experimentally injected failures.
- Fault windows define the recorded incident intervals.
- Topology describes the experimental infrastructure.

Fault-injection labels are evaluation references and must not be
exposed to the RCA agent as diagnostic evidence.

### Limitations

- The dataset represents controlled experimental environments.
- Fault injection does not guarantee observable effects in every log.
- Multiple incidents may overlap.
- Timestamps require consistency verification.
- The initial subset does not include all available NF metrics.
- Results cannot automatically be generalized to production networks.

### Selection Decision

**Status:** Provisionally accepted for development and evaluation.

The selected subset will undergo automated integrity, temporal
consistency, and evidence coverage checks before final acceptance.

Additional files may be incorporated when required by the
selected evaluation scenarios.
